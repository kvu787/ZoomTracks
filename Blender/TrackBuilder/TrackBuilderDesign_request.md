Write `TrackBuilder.py` for Blender 4.5.12 and meet the requirements below.
Use `SampleInput.blend` as an example input, but do not modify it.
Generate ten `.blend` files containing example inputs and outputs generated by the script.

The script must use only Blender's bundled Python standard library, `bpy`, and
`mathutils`; it must not require third-party packages. Its public entry point is:

```python
build_track(W, H, segment_length, material_names)
```

The function operates on the current file and returns the newly committed
`Output` collection. When run from Blender with `--python`, the script also
provides `--build` and `--generate-examples` command-line modes.

# Track Builder design

## Rollback safety

- If an output already exists, preserve it until the script execution fully succeeds.
- If the script succeeds, replace the previous output with the new output.
- Construct new datablocks in a uniquely named temporary collection. On failure,
  remove the temporary collection and leave the previous `Output` unchanged. On
  success, commit the temporary collection as `Output`, then remove the previous
  collection and its orphaned generated mesh/object datablocks.
- `Input` and an existing `Output` must not be nested within each other or share
  objects. Reject such a file before constructing output.

## Orientation convention

Clockwise (CW) and counterclockwise (CCW) are defined as viewed from global +Z looking toward the XY plane.

## Script inputs

The script has the following parameters:

- `W`: Barrier thickness; must be a finite value greater than zero
- `H`: Barrier height; must be a finite value greater than zero
- `segment_length`: Target length of a colored barrier segment, measured along an input outline; must be a finite value greater than zero
- `material_names`: Ordered list of Blender material names used for the repeating barrier-color sequence
  - The list must contain at least one item
  - Every item must be a non-empty string naming an existing material in `bpy.data.materials`
  - Repeated material names are allowed

## Inputs

- A `.blend` file
- A collection named `Input`
- The collection recursively contains two or more outline objects
- An outline object:
  - Is a mesh or curve object
    - For a curve object, the outline is the geometry produced by evaluating the curve at its configured resolution (for example, `bpy.data.curves["NurbsCurve"].splines[0].resolution_u`)
  - Is purely two-dimensional (all Z-coordinates must be zero)
  - Contains no faces
  - Forms a closed loop of edges
  - Does not intersect itself or any other outline object
- There are three types of outline objects:
  - Ground outline: Required; exactly one
  - Outer track outline: Required; exactly one
  - Inner track outline: Optional; zero or more
- The script must use the geometry of the outline objects to classify each one as ground, outer track, or inner track
- The outline objects must have one or two levels of nesting:
  - Level 1: The ground outline must enclose the outer track outline
  - Level 2: Any inner track outlines must be enclosed by the outer track outline
- Each outline object must have exactly one material assigned to it

The Input collection and its contents must not be modified.

### Curve evaluation

The input outlines must be converted to dependency-graph-evaluated geometry, including modifiers.

### Coordinate space

All inputs must be converted to world space before validation.
All vertices in the resulting world-space meshes must have a Z-coordinate of zero.

### Validation rules

- All objects found recursively within the `Input` collection must satisfy the outline-object definition
- Each object must contain exactly one closed loop of edges
- Objects must not contain loose vertices, zero-length edges, branches, or duplicate consecutive points
- Each curve must contain exactly one cyclic spline
- Outlines must not touch
- An inner outline must not be nested inside another inner outline
- Let `D` be the diagonal length of the XY bounding box containing all evaluated
  input vertices. Use `epsilon = 1e-7 * max(1, D)` for world-space distance
  comparisons involving Z-coordinates, zero-length edges, duplicate points,
  touching, intersections, containment boundaries, and collinearity. Distances
  less than or equal to `epsilon` count as touching or equal.
- `W`, `H`, `segment_length`, and `material_names` must satisfy all requirements in the Script inputs section
- Every name in `material_names` must resolve to an existing Blender material

## What the script does

After evaluating and validating the unmodified input geometry, copy each loop to
world-space working data. In the working copy only, repeatedly remove a middle
vertex when it is collinear within `epsilon` with its neighbors and both adjacent
edges travel in the same direction. Never merge a backtracking vertex. The
`Input` collection, its objects, and their datablocks must never be modified.

Accept either input winding. Normalize every working loop to CCW, then rotate its
vertex order so the lexicographically smallest world-space `(X, Y)` vertex is
first. Sort inner outlines by this canonical starting point and then object name.

Given this input, the script must generate:

1. Flat meshes (called fill meshes) that represent the ground, track, and enclosed islands
2. One-sided, thickened, color-segmented, gapless, barrier meshes from the outer and inner track outlines

Requirements:

- The fill meshes must be properly triangulated. Each fill mesh must fill its intended region without overlapping faces or faces that cross an outline boundary. Each fill mesh must be assigned the material from its corresponding input outline object.
- Every output object must be placed in a collection named `Output`.
- All triangles in the ground, track, and island meshes must face global +Z.
- The `Input` collection and its objects must not be modified
- The script must throw descriptive exceptions when input preconditions are not satisfied

## Outputs

### Ground mesh

The ground mesh is a flat mesh that fills the ground outline but excludes the outer and inner track outlines.

### Track mesh

The track mesh is a flat mesh that fills the outer track outline but excludes the inner track outlines.

### Island meshes

The island meshes are flat meshes that fill the inner track outlines.

### Barriers

#### Generate flat geometry

The fundamental barrier mesh geometry is generated from a simple algorithm:

- For each outer track outline and inner track outline edge:
  - Extrude the edge away from the track along the perpendicular axis by `W`.
  - Upscale the edge and its two neighboring extruded edges until they intersect, resulting in two intersection points
  - The edge that connects those two intersection points forms one edge of the barrier
  - The other edge of the barrier is formed by the existing outline's edges
- At this point, you should have a flat 2d mesh that resembles a one-sided thickened outline of the outline edge loops

The algorithm doesn't do anything "fancy":

- If the outline shape or `W` causes barriers to self-overlap or bleed into the track mesh area, that's fine
- Treat offset edges as infinite lines when computing miter intersections.
  Self-overlap between barrier portions and self-intersecting barrier n-gons are
  accepted as the direct result of this algorithm; do not perform boolean cleanup.
- If numerical degeneracy leaves fewer than three distinct vertices in a barrier
  segment, throw a descriptive construction exception and preserve the previous
  output.

#### Slice into segments

This step slices up the barrier meshes into colored segments.

- Measure the length of the barrier mesh by summing up the edge lengths in its track outline
- Compute `ratio = outline_length / segment_length`. If `ratio` is within a
  relative tolerance of `1e-10` of an integer, use that integer. Otherwise use
  `segment_count = max(1, floor(ratio))`. The adjusted segment length is
  `outline_length / segment_count`. Thus segments are normally no shorter than
  the target; when the target exceeds the perimeter, create one shorter segment.
- Reject a build if any one outline would require more than 10,000 barrier
  segments.
- Use the canonical first vertex as the starting point and traverse CCW
- Use the adjusted `segment_length` to slice up the barrier mesh
  - Every "slice point" must lie on an edge or vertex of the track outline mesh
  - For a slice point `p = lerp(original_edge_start, original_edge_end, t)`, map
    it to `q = lerp(offset_miter_start, offset_miter_end, t)`.
  - A segment spanning outline corners must retain all intervening original
    vertices and corresponding miter vertices, in reverse order along the offset
    side, so adjacent segments are gapless.
- Create a 2d polygon single face object for each of these segments
- Now, you should have a bunch of flat barrier segment objects

#### Color segments

Assign a material to each barrier segment from `material_names` in a repeating
fashion. Restart the sequence at `material_names[0]` independently for every
outer or inner barrier loop.

#### Extrude to 3D

Take each flat 2d barrier segment mesh and extrude it by `H` along the global +Z axis.
